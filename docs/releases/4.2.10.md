# Vox Agent 4.2.10 (macOS composer candidate)

Status: **candidate, not a published release**. The product version moved from
4.2.9 to 4.2.10 on 2026-10-18 (owner decision) so that a macOS build carrying
the new composer can be installed over the owner's 4.2.4 without reusing the
4.2.9 number, which [`4.2.9.md`](4.2.9.md) reserves for the dual-platform
(macOS and Windows) candidate line. The 4.2.9 GAP table and its Windows
preview tags are unaffected; this file records the macOS-only candidate.

Source: `main` of `osborn-studio/vox-agent` after PRs #1 to #5. The version is
pinned once across the engine (`pyproject.toml`, `engine/__init__.py`), the
macOS bundle (`Info.plist`), the Tauri shell (`package.json`, `package-lock.json`,
`Cargo.toml`, `Cargo.lock`, `tauri.conf.json`), the root `package-lock.json`
and `docs/RELEASE.md`; `tests/test_release_version.py` enforces it.

## What changed since the installed 4.2.4

- **Codex-style composer.** The chat input is two rows: a text area that grows
  upward with content to 176pt (about eight lines) before scrolling, and a
  control row below it with Translate on the left and the Polish model badge
  (opens Models settings when no model is configured), mic and send on the
  right. Geometry lives in `ChatLayoutMetrics`; DESIGN.md records the two-row
  contract as an owner decision of 2026-10-18.
- **Translate in the composer.** The Translate chip translates the draft in
  place (Chinese ⇄ English, direction detected from the text) using the same
  provider and model as Polish; Restore brings the original draft back. A
  translated draft is sent as is, without a second Polish pass.
- **Translate in the Feishu text send box.** The same chip, backed by the same
  translator, rewrites the Feishu draft in place with Restore, inline progress
  and inline failure text. Nothing is sent automatically: the translated draft
  waits for the explicit "发送文字" action, which is disabled while a
  translation runs.
- **Polish failures are visible.** When Polish fails (network, timeout,
  provider error) the composer shows the reason inline and keeps the draft
  instead of sending the unpolished text silently.
- **Timeline translation removed.** The unreachable per-message translation
  plumbing in the Feishu timeline is gone; the composer Translate replaces it.
- **Feishu renewal diagnostics.** Session renewal logs one line per attempt
  (outcome, hashed user, device prefix, upstream code) and the account view
  shows session validity and the last renewal outcome as plain captions. Raw
  audio, transcripts and tokens never enter these logs.
- **CI restored.** `.github/workflows/verify.yml` runs Python lint and tests,
  TypeScript, mobile, Windows Tauri, the pinned RustSec audit, Swift tests and
  the Swift release build on GitHub-hosted runners for pull requests.
  `.github/workflows/release-dmg.yml` builds the macOS DMG on demand.

## Building the DMG

Actions › Release DMG › Run workflow on `main`, leaving the version empty (it
must equal the Info.plist version, 4.2.10), or:

```bash
gh workflow run release-dmg.yml --repo osborn-studio/vox-agent --ref main
```

The run uploads `VoxAgent-v4.2.10-cloud.dmg` and `SHA256SUMS.txt` as the
artifact `vox-agent-v4.2.10-dmg` (30-day retention); the checksum is also
printed in the job summary. The 4.2.9 proof run of the same workflow on the
`macos-26` hosted runner is
<https://github.com/osborn-studio/vox-agent/actions/runs/39158307961>.

## Signing

The DMG is **ad-hoc signed**. This repository holds no Developer ID
certificate or notarization credential, so Gatekeeper blocks the first launch
of the installed app. Right-click (or Control-click) `Vox Agent.app` in
Applications and choose **Open** once; later launches open normally. The bundle
identifier (`com.osborn.voxagent`) and the `VoxLog` persistence identifiers are
unchanged, so the install replaces 4.2.4 in place and keeps Keychain items and
local data.

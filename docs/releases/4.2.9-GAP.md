## How to fill this file

- One block per candidate. Use the immutable candidate tag (`v4.2.9-preview.N` for a
  Windows preview, `v4.2.9` only for the final dual-platform release).
- A feature row is `PASS` only when every applicable layer has accepted evidence.
  A partially passing row stays `GAP` and lists the missing sub-capability.
- `NOT_APPLICABLE` needs a scope reason. "Not implemented yet" is a `GAP`, never N/A.
- Never copy a status from another candidate, commit, or platform.

## Known limitations to disclose

- Valid Authenticode does not guarantee the absence of a SmartScreen warning for a new publisher.
- DPAPI-protected local data is bound to the Windows user profile; it is not portable across machines.
- `delivered` means the service reported delivery with a message ID; it does not prove current permission.
  Receipts and `/me` carry no authorization revision (T03c GAP,
  `docs/decisions/2026-10-09-authorization-revision-gap.md`); lost permission is detected through
  401/403, a project-catalog refresh or a failed renewal only.
- The engine the Windows desktop starts accepts only that desktop launch (per-launch secret on
  stdin, signed requests; T29). The TypeScript gateway (`services/api-ts`) cannot use that engine:
  a gateway deployment needs its own engine. Relaying desktop-engine access to the gateway would
  need a separate, authorized design.
- Engine process ownership (Windows Job Object, PID-bound port check; T29b native) is not verified
  until a Windows run.
- Native capture (T26) now has one owner per session, but its buffer is still in memory for up to
  one hour (a 48 kHz stereo device can reach about 1.4 GB) and resampling to 16 kHz uses linear
  interpolation without an anti-aliasing filter. A duration/byte budget and a filtered resampler,
  with spectrum and long-capture memory evidence, remain to be done; real-microphone behaviour is
  verified only on a Windows device.
- Local ASR models (T31) install only through the verified cache: a pinned schema-1 manifest
  (`engine/model_manifests/`), byte-exact size and SHA-256 checks, staging and atomic activation.
  Pinned: SenseVoice int8 (`model.int8.onnx` + `tokens.txt` from the k2-fsa maintainer's
  Hugging Face repo at commit 2365baea, cross-checked against its LFS SHA-256 and git blob
  hash) and Silero VAD (k2-fsa `asr-models` release). The Silero release URL is not
  commit-pinned; its bytes are, so a changed asset fails verification instead of installing.
  The SenseVoice license is the FunASR model license (not an OSI license). Existing unverified
  model folders are still used as a fallback when no verified revision is active.
  Offline import (`scripts/fetch_sherpa_model.py --from FOLDER`) and reuse of identical local
  copies (other revisions, the unverified bundle older versions downloaded) avoid downloading
  the same model twice (T32); every reused byte is verified and the legacy folder is left as is.
  Neither Mac used for development has the legacy bundle, so reuse is verified with synthetic
  files only. Reused and imported files are refused behind a link and checked from a single
  no-follow open; a directory swapped between the check and the open is not detected, so the
  copied bytes' SHA-256 remains the guarantee (Windows has no O_NOFOLLOW; reparse points are
  refused by attribute).
- Feishu history and text sending (T25) have a verified client core: history pages are checked
  against the conversation and the server's read mode (a group without a shared-read policy
  shows only the user's own submissions and says so), cursors restart on a changed
  authorization, and sends keep one eventId per message so retries cannot duplicate it.
  The outbox lives in memory only: text that was never confirmed is lost on restart and the
  user must decide whether to write it again. Encrypted persistence (with T07b), the Tauri IPC
  and timeline wiring, and a run against a real Feishu tenant remain to be done.
- Private records and the weekly draft (not in the preview scope, plan C-01): the private
  mutation journal (T18a), weekly source coverage (T21) and the private create/readback and
  list/search service with main-window-only IPC (T18b, T19) are verified against the
  real-service fixture. No private journal is configured until a key provider exists on the
  platform (T07b), so the commands answer `journal_unavailable`. Edit/withdraw (T20: edits
  against the revision the user saw, withdrawals only with an explicit confirm) and the weekly
  draft core (T22: separate team and picked-private sections, copy gated on a team recheck and
  a private reference check) are verified the same way. Clearing the view on sign-out, collapse,
  hide or lock drops private plaintext and late results while keeping saved mutations (T23b).
  The right panel now has a private inbox (save, list this week, edit against the shown
  revision, two-click withdraw, picks for the weekly draft) and a weekly draft (load a week,
  exclude sources, write and edit the draft, check-and-copy), cleared in the page and in Rust
  on panel collapse, hidden or locked window and account end (not on a mere window switch).
  Team-only weekly drafts work without the private journal; private notes and drafts with
  private picks wait for T07b. Verified with node module tests, an axe WCAG 2.2 AA scan (no
  violations, light and dark) and screenshots of a static page; not run inside the Tauri shell. Weeks run Monday to Monday in Asia/Shanghai time,
  as on macOS, and are not localized. The private journal has no rollback anchor; a restored
  copy can only resend mutations with their original ids and revisions.
- Conversation voice drafts (T27) follow the macOS rules as a verified page module
  (`src/context/conversation-draft.js`: destination frozen at dictation start, late or
  cancelled transcripts refused, recovery for a switched or revoked conversation, never sent).
  The Feishu conversation timeline and composer it plugs into are not built yet.
- The Context / three-pane baseline subset (T01c) is mapped against macOS v4.2.8.1
  (`docs/verification/windows-t01c-context-baseline.md`): not called on Windows are
  `auth/feishu/renew`, `me`, `link-previous` and `context-private-authorization`; Feishu
  conversations are not sidebar targets; sync and online update have no sidebar controls.
  The full baseline inventory (T01) is still to be done.
